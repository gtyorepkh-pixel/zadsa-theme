- **Chromium حقيقي** (`npm run e2e`، 50 فحصاً ✓): HTML السيرفر == HTML الـJS لكل أداة؛ رابط النتيجة يملأ النموذج؛ النموذج يعمل **بدون JS** (GET)؛ أحداث GA4 (`tool_start`,`tool_complete`) بلا أي بيانات شخصية؛ منطقة `aria-live`؛ رسالة واتساب فيها الحي؛ التذكير: لا يُرسَل شيء بدون موافقة، والموافقة غير مفعّلة مسبقاً، وحمولة الطلب سليمة؛ ملف `.ics` يُحمَّل ولا يحوي اسماً ولا رقماً؛ الإعدادات (استهلاك/شرائح) تغيّر الناتج؛ حجم كل JS < 30KB (أكبرها 17KB).
- **Lighthouse (جوال، تحكّم افتراضي):** على صفحات الاختبار المولَّدة (بدون CSS/خطوط ثيمك): المكيف **أداء 100 / وصول 100 / Best Practices 100 / SEO 90**، الرش والخزان نفس الأرقام. SEO 90 سببه الوحيد غياب meta description (يضيفه Yoast/الثيم في الصفحة الحقيقية). **CLS = 0**. هذه ليست قياس موقعك الحقيقي (LiteSpeed، الثيم، GA، الخطوط) — شغّل Lighthouse عندك قبل الاعتماد.

## 6) ما لم أستطع اختباره هنا
تفعيل الإضافة وشاشات الإعدادات داخل WordPress الحقيقي، حفظ الاعتماد، قالب الصفحة مع الثيم الحقيقي، REST/cron الحيّ (التذكير يُختبر هنا بخادم وهمي)، تنزيل `.ics` عبر `template_redirect` على LiteSpeed (لا يوجد كاش لأنه no-cache لكن جرّبه)، ظهور رابط الخصوصية الحقيقي.

## 7) قرارات اتخذتها بنفسي
1. **رابط النتيجة يُحسب على السيرفر أيضاً** (`?l=4&w=4…`) لأنه شرط «النتيجة في الرابط» وfallback بلا JS؛ الـcanonical يظل الصفحة الأساسية.
2. **نموذج التذكير مخفي حتى يعمل JS** (التسجيل يحتاج رمز REST آمن مع الكاش) — بلا JS تبقى النتيجة + `.ics`.
3. **تذكير الخزان يوم الموعد نفسه** (لا «قبله بأيام») كي لا أضيف رقماً جديداً؛ يمكن إضافته لاحقاً كإعداد.
4. **لم أخمّن استهلاك الفرد** (لا مصدر موثوق عندي) فتُركت الخاصية فارغة وتخفي سطر «يكفي كم يوم».
5. **شارة «إرشادي» (لا «تقديري») لأداة الرش** لأن ما يحكم هو توجيه الفني.
6. حدود تحقق تقنية ثابتة في الكود (مساحة ≤ 1000 م²، بُعد الخزان ≤ 100 م، ارتفاع ≤ 20 م) — حدود صحة مدخلات لا قيم أعمال.
7. **الأمثلة المحسوبة**: أحوال الإدخال (مثل «غرفة 4×4») ثابتة في الكود كأمثلة توضيحية، والنواتج تُحسب من إعداداتك.
