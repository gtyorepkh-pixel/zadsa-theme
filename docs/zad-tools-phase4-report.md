## 2) ما أُضيف
**الموسوعة:** لكل حشرة: الأسماء الشائعة، الاسم العلمي، علامات الوجود، الأماكن، النشاط والموسم، مستوى الخطر، الوقاية، **الخدمة المرتبطة** (زر + رابط داخلي)، أسئلة شائعة، الصورة البارزة بنصها البديل من مكتبة الوسائط، والمحتوى الحر. الحقل الفارغ **لا يُطبع**. خصائص التعريف (لون، حجم، مكان، علامة، أجنحة نعم/لا/أحياناً) مفرداتها قابلة للتعديل في «أدوات زاد ← الموسوعة والمعرّف» والفئات من أمر التنفيذ.
**المسودات:** «موسوعة الحشرات ← إنشاء المسودات» ينشئ **عند الضغط** مسودة فارغة لكل اسم ناقص من قائمة قابلة للتعديل (الصراصير، النمل، النمل الأبيض، بق الفراش، الفئران) ولا تظهر للزوار.
**المعرّف:** 5 أسئلة (المكان، الحجم، اللون، الأجنحة، أوضح علامة) بخيارات برموز، ونتيجة = أقرب حتى 3 حشرات بنسبة تطابق وصورتها ورابط صفحتها وزر خدمتها؛ تحت الحد «القوي» لا يجزم بل يطلب صورة على واتساب برسالة جاهزة فيها إجاباتك.
**التقرير:** مسودة شهرية تُولَّد بزر، أرقامها **تُجمَّد** داخل المسودة؛ رسم أعمدة لأكثر الحشرات، خط للاتجاه 12 شهراً، أكثر الأحياء (بشرط الحد الأدنى)، مقارنة الرياض وجدة، المنهجية، CSV، وكود تضمين للرسمين يرجع برابط للتقرير؛ `Dataset` + `Article`.

## 4) روابط الاختبار المحلي (صفحات عادية)
- معرّف الحشرات: صفحة بقالب «أداة زاد» (`/tools/pest-identifier/`) — يفتح بعد نشر **3 حشرات على الأقل** فيها خصائص تعريف + اعتماد النسبة. مثال رابط نتيجة: `…?pl=wood&sz=small&co=white&wg=some&sg=sawdust`
- فهرس الموسوعة: صفحة عادية `/pests/` فيها `[zad_pests]` (لا أرشيف تلقائي كي لا تُولَّد صفحات بذاتها).
- التقارير: صفحة عادية `/pest-report/` فيها `[zad_pest_report]`؛ كل شهر على `/pest-report/2026-10/`.
- سير العمل: «تقارير الحشرات ← توليد واستيراد» ← اختر الشهر ← تفتح المسودة ← اكتب «ملاحظات المحرر والنصائح» ← انشر (يُرفض النشر مع ذكر السبب إن نقص شيء).

## 5) الاختبارات
- `npm test`: **76 اختبار JS ✓** + PHP: المرحلة 0 (37)، الطلبات (41)، الأدوات 2 (59)، 3 (54)، **4 (73) ✓**.
- **التطابق JS/PHP للمعرّف:** 8 حالات + 3 حالات بأوزان مختلفة، والـHTML **بايت ببايت** (بطاقات الصور). أمثلة يدوية: الإجابات الخمس المطابقة كلها = 100%؛ سؤال واحد من خمسة مطابق = 100% (غير المتأكد منه لا يدخل المقام)؛ مكان بوزن 2 + أجنحة بوزن 1 = 100% مقابل 67%؛ «أحياناً» تطابق أي إجابة؛ الخاصية غير المسجلة لا تطابق.
- **التقرير (اختبارات PHP بدوال صافية):** طلب تنظيف مكيفات لا يدخل التقرير؛ الحي 4 طلبات أو 3 **لا يُسمّى** (لا في الصفحة ولا في الـCSV) ويُعلن عدد الأحياء المخفية فقط؛ المنحنى = 12 شهراً تنتهي بشهر التقرير وما خارجها لا يُعدّ؛ **النشر مرفوض** بلا ملاحظات المحرر أو بلا حد أدنى مضبوط أو بطلبات أقل منه؛ رسمان SVG سليمان XML ومهرّبان وبهما `title/desc`، وأطوال الأعمدة متناسبة؛ **استيراد CSV يرفض الملف كله لو فيه أي عمود زائد (جوال/اسم/إيميل/ملاحظات)**، ويقبل الأرقام العربية والفاصلة المنقوطة؛ الـDataset بتغطية زمنية وتوزيع CSV وبلا ترخيص مخترع ولا تقييمات.
- **Chromium (146 فحصاً ✓):** المعرّف: HTML السيرفر == JS، رابط النتيجة يملأ الفورم، بدون JS يعمل بـGET، التطابق الضعيف لا يجزم ويطلب صورة، بلاطات الخيارات ≥ 44px؛ التقرير على الجوال: رسمان + جداول بيانات مقروءة بجانبهما + بلا تمرير أفقي للصفحة.
- **Lighthouse (جوال):** المعرّف: أداء 100 / وصول 100 / BP 100 / SEO 90 (meta description يضيفه Yoast)؛ التقرير: **100 / 100 / 100 / 100**؛ CLS = 0. على صفحات اختبار مولّدة، لا على موقعك.
- Rich Results: بنية JSON-LD فقط (`Article`+`FAQPage` للحشرة، `Dataset`+`Article` للتقرير، بلا تقييمات).

## 6) لم يُختبر هنا
كل ما يخص WordPress الحقيقي: ظهور `/pests/…` و`/pest-report/…` بعد الرفع، الصناديق وشاشات «توليد واستيراد»، رفع CSV فعلي، **حارس النشر عبر `wp_insert_post_data`** (اختبرت منطقه لا اتصاله)، استعلام الطلبات المكتملة (`_zt_service_date` بين تاريخين) على بياناتك، الصور البارزة والنص البديل، تداخل Yoast/خريطة الموقع، وقالب الثيم الحقيقي.

## 7) أخطاء وجدتها الاختبارات قبل التسليم (أُصلحت)
1. حشرة بلا خصائص تعريف كانت ستدخل المعرّف (القيمة الفارغة تتحول لمصفوفة بعنصر فارغ).
2. كلمات الربط الافتراضية «نمل أبيض» لم تكن لتطابق «النمل الأبيض» (ال التعريف والهمزة) — صار المطابق يهمل «ال» والتشكيل وأشكال الهمزة.
3. رسوم SVG كانت تُقصّ من اليمين داخل صفحة RTL — أُصلح اتجاه النص.
4. دالة التاريخ لم تدعم الطرح (يوم قبل أول الشهر) — أُصلحت في JS وPHP مع اختبار تطابق.

## 8) قرارات اتخذتها بنفسي
1. **لا أرشيف تلقائي** للموسوعة ولا للتقارير (التزاماً بمنع توليد صفحات بالقواعد)؛ الفهرس صفحتك بـshortcode.
2. التقرير = **نوع محتوى بلا زر «إضافة»**: لا يُنشأ إلا بالتوليد؛ والمنشور مجمّد (أعد تحويله لمسودة لإعادة التوليد).
3. صفحة `/pest-report/` تعرض **ملخص آخر تقرير + الأرشيف** وليس نسخة كاملة، لتجنب تكرار المحتوى.
4. **نسبة التطابق** = أوزان إجاباتك المنطبقة ÷ أوزان ما أجبت عنه، وتُشرح في «إزاي بنحسب»؛ لا تُحشى القائمة إلى 3 فتُعرض فقط الحشرات المطابقة لشيء.
5. الاستيراد على خطوتين (معاينة ثم تأكيد) وبدفعات قابلة للحذف؛ **لا تستورد فترة موجودة أصلاً** في الطلبات المكتملة وإلا تتكرر الأرقام.
6. إجابات المعرّف لا تُحفظ على الخادم (تبقى في الرابط).
7. تحذير: السكيما تضيف `reviewedBy` للمراجع الفني المحدد في الثيم إن وُجد، بلا أي اسم مخترع.

## 9) مطلوب منك
- كتابة محتوى الحشرات (3 على الأقل بخصائص تعريف وصورة بنص بديل) ثم اعتماد نسبة التطابق.

- إنشاء الصفحات الثلاث (المعرّف، فهرس الموسوعة، `/pest-report/`).
